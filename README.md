# AxolotlBucketLabs Community

This repository defines the community roles and application process for [AxolotlBucketLabs](https://github.com/AxolotlBucketLabs).

AxolotlBucketLabs maintains community forks of PocketMine-MP plugins and libraries for Axolotl-PM. The organization also welcomes people who enjoy the ecosystem, want to test projects, share feedback, improve documentation, or contribute code when they have time.

## Applying for a role

Open a [role application issue](https://github.com/AxolotlBucketLabs/community/issues/new?template=role-application.yml) and select the role you want to apply for. Include your GitHub profile, relevant contributions or experience, and what you would like to help with.

Application issues are public. Do not include passwords, private contact details, personal documents, or other sensitive information. Use the [Discord server](https://discord.gg/Pk4FrNvHnM) when a private discussion is needed.

Applications are reviewed individually. Meeting the suggested criteria does not guarantee approval. A role is assigned only after manual verification, and a Discord role does not automatically grant GitHub permissions.

AI-assisted contributions are welcome when the contributor understands, reviews, tests, and takes responsibility for the submitted work.

The machine-readable role policy is available in [`roles.json`](roles.json). Changes to the role policy must be proposed through a pull request.

## Community roles

- `Lab Founder` is reserved for the founder and owner of AxolotlBucketLabs. It cannot be applied for.
- `Lab Associate` is a trusted co-founder or administrator who helps manage the organization, its projects, and its members. It is assigned by invitation from the Lab Founder.
- `Lab Member` is an official member of the GitHub organization. Repository access is granted separately according to project needs and established permissions. Applications are accepted.
- `Lab Maintainer` is responsible for the ongoing development, maintenance, and quality of at least one organization project. The role is project-specific and does not automatically grant organization administration privileges.
- `Lab Collaborator` is a trusted external collaborator who actively contributes to one or more organization projects and may receive repository-level access. Contribution quality and trust matter more than a fixed number of pull requests.
- `Lab Contributor` is a community member who has made at least one meaningful contribution to an organization project. A trivial change made only to obtain a role does not qualify.

Members may hold multiple roles when their responsibilities justify it. Organization membership, project maintenance, repository access, and Discord roles are separate decisions.

## Review principles

- Review decisions are based on meaningful work, communication, trust, and project fit.
- Suggested contribution counts are guidelines, not automatic approval rules.
- Project proposals must fit the organization's scope and use an appropriate license.
- Maintainers may request more information before making a decision.
- Roles can be changed or removed when the responsibilities or trust behind them no longer apply.

Roles recognize meaningful contributions, responsibility, and trust. They are not just titles.

## Contributing to this repository

Use a pull request to propose changes to the role policy, application process, or community documentation. Keep changes focused and explain the reason for the change.
