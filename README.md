# AxolotlBucketLabs Community

This repository defines the community roles and application process for [AxolotlBucketLabs](https://github.com/AxolotlBucketLabs).

AxolotlBucketLabs maintains community forks of PocketMine-MP plugins and libraries for Axolotl-PM. The organization also welcomes people who enjoy the ecosystem, want to test projects, share feedback, improve documentation, or contribute code when they have time.

## Applying for a role

Open a [role application issue](https://github.com/AxolotlBucketLabs/community/issues/new?template=role-application.yml) and select the role you want to apply for. Include your exact Discord username, relevant contributions or experience, and what you would like to help with. Link public repositories, pull requests, releases, or other useful evidence where possible. The GitHub account that opens the issue is visible to maintainers.

Application issues are public. Do not include passwords, private contact details, personal documents, or other sensitive information. Use the [Discord server](https://discord.gg/Pk4FrNvHnM) when a private discussion is needed.

Applications are reviewed individually. Meeting the suggested criteria does not guarantee approval. A role is assigned only after manual verification, and a Discord role does not automatically grant GitHub permissions.

AI-assisted contributions are welcome when the contributor understands, reviews, tests, and takes responsibility for the submitted work.

The human-readable role and permission policy is available in [`PERMISSIONS.md`](PERMISSIONS.md). Project ownership and access are documented in [`PROJECTS.md`](PROJECTS.md) and [`projects.json`](projects.json). The machine-readable role data is available in [`roles.json`](roles.json), while the current member registry is available in [`members.json`](members.json). Changes to these files must be proposed through a pull request.

## Role summary

- `Lab Founder` is reserved for the founder and owner of AxolotlBucketLabs.
- `Lab Associate` is a trusted administrator who helps manage the organization by invitation.
- `Lab Fellow` is an honorary recognition role for a person widely respected by the organization's leadership and project members. It grants no organization or project access.
- `Lab Member` is a trusted official GitHub organization member, normally after at least two meaningful merged pull requests. Repository access is granted separately.
- `Lab Maintainer` is responsible for the ongoing maintenance of at least one organization project.
- `Lab Collaborator` is an external contributor with access to selected organization repositories.
- `Lab Contributor` is a community member who has made a meaningful contribution to an organization project.

Read [`PERMISSIONS.md`](PERMISSIONS.md) for the full responsibilities, application criteria, and permission boundaries. Members may hold multiple roles when their responsibilities justify it.

## Review principles

- Review decisions are based on meaningful work, communication, trust, and project fit.
- The normal `Lab Member` threshold is two meaningful merged pull requests, but approval still depends on quality, communication, trust, and project fit.
- Exceptions may be considered for approved maintainers or substantial ongoing contributions that are not represented by pull requests.
- Project proposals must fit the organization's scope and use an appropriate license.
- Maintainers may request more information before making a decision.
- Roles can be changed or removed when the responsibilities or trust behind them no longer apply.

Roles recognize meaningful contributions, responsibility, and trust. They are not just titles.

## Contributing to this repository

Use a pull request to propose changes to the role policy, application process, or community documentation. Keep changes focused and explain the reason for the change.
